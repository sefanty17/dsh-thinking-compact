## 结论先行

1. **缩句风格解决了上次的「步数变多」**：A 68 步 / B 68 步，完全一致。上一次 JSON 三段式是 A 29 步 / B 45 步（B 多 55%），模型不信任纪要式二手历史、反复重做。换成第一人称缩句后这个现象消失了。
2. **但 token 与成本仍然亏**：B 省了 8.3% 总 token，成本却高 38%，耗时多 77%。主因不是摘要本身，也不是整段替换挪位，而是**压缩结果没有驻留在会话里、每个请求都重压一遍**（详见下文）。
3. 两组完成度都是 5/5 轮、每轮验收通过率 1.0，没有功能损失。

## 为什么省了 token 反而更贵

### 根因：压缩结果没有驻留，每个请求都重压一遍

代理只改转发给上游的那份 `payload["messages"]`，**不回写 DSH 的会话历史**。扫过全部 DSH session 日志，含卡片标记的文件是 0 个。于是 DSH 每个请求都把未经压缩的完整原文再发一遍，代理每个请求都重新选段、重新调模型生成一张新卡片。

证据：

- `spine-cuts.jsonl` 里 `seq_start=37` 连续出现 4 次，`seq_end` 从 40 → 42 → 44 → 46，`tokens_before` 从 8,859 涨到 35,558 —— 同一段历史被反复吞进去重压。
- 卡片是模型现生成的，每次文本都不同。上游看到的是「原文前缀 + 一张每轮都不同的卡片」，前缀在切点处断裂，切点之后的 prompt 全部缓存未命中。
- B 组 idx 29~33 连续 5 个请求各约 3 万 miss（占当次 prompt 的 60%，`hit` 只有 2.2 万）；A 组同期只有 idx 26 / 31 两次零散 miss。B 组其余请求的 miss 与 A 组一样都在 150~850 量级，说明**平常的前缀缓存是好的，只在重压窗口崩掉**。

连锁代价：

- 未命中 token 9.7 万 → 19.4 万（翻倍），未命中单价是命中价的 30 倍，直接把省下的 prompt token 吃回去还倒贴；
- 8 次压缩调用累计 359s，其中多次是同一段历史的重复劳动；
- 卡片每轮都变，模型反复重新推理：思考字符 +44%、输出 token +54%，进一步推高输出费用。

### 次要原因：卡片本身太大

`tools_policy="keep"` 要求工具结果原文一字不改完整进卡片，思考缩句省下的量填不进这个缺口。5 轮只有 8 次压缩成功，单次 reduction 仅 2.2% / 3.3% / 3.3% / 0.02%；未命中原因主要是 `no_closed_round` 与 `reasoning_below_threshold`（4000 token 阈值）。

### 澄清一个容易误判的点

整段替换**没有**挪动切点之后的消息对象：`apply.py` 里有两道指纹校验，切点前原文逐字节不动，切点后的消息对象身份也不变（测试里 `test_prefix_and_tail_objects_unchanged` 覆盖）。所以不能把 miss 翻倍归因于「替换导致前缀指纹变了」。问题在于压缩结果只活在这一次转发里，下一轮又从原文重来。

## 已修的账本问题

- 两组都走代理（A 组 `compact=False` 纯转发），账本同源；
- 单轮超时 600s → 1800s，B 组第 1 轮 630s 正常完成，不再被掐；
- `reasoning_tokens` 补上采集：DSH 未给精确值时按 `thinking_chars//3` 估算并标 `reasoning_tokens_estimated=true`，不冒充计费值；
- 摘要输出加 16384 token 上限与截断检测，截断即整段保留原文；
- `keep_rounds` 默认 0（所有可切轮次都压），不再出现 `recent_tool_rounds_kept`。

## 下一步建议

1. **最优先：让压缩结果驻留**。这轮测的其实是「每请求临时重压」，不是设计里说的「切一次、后续轮次一直带卡片」。可行方向：
   - 代理侧按 session 维护压缩后的消息数组，把每次请求的原文增量追加到本地状态，转发时用本地状态而不是 DSH 的原文；
   - 或让 DSH 侧真正落刀（回写会话），但那要改宿主，超出纯代理方案。
   驻留后卡片文本固定，前缀缓存会恢复，重复压缩的 359s 也一并消失。
2. 保持缩句风格（步数 68 vs 68 已证明有效，别退回 JSON 三段式）。
3. `tools_policy="keep"` 是卡片体积大头，若愿意放宽「工具结果原文完整进卡片」，改成省略式能显著降低卡片体积；但这与「工具调用不受影响」的原始约束冲突，需先确认。
4. 5 轮样本仍小，结论稳定后再跑 30 轮全量。
